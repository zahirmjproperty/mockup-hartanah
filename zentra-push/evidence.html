Structured data first

For feeds and APIs the response body is parsed and the identifier is stored. For portals where the only confirmation is the public page, the page is fetched and the reference number is asserted to be present in the markup.

A screenshot as the fallback

When the read-back cannot be parsed, a timestamped screenshot is attached to the ledger row so a human can settle the question in seconds rather than re-checking the portal.

Failures stay visible

A placement that was submitted but never verified sits in the ledger as Submitted indefinitely. Nothing is auto-closed just because time passed.
