What the live system enforces

DutyHow the system enforces it
Consent on record Consent flag + date + purpose + evidence document per contact; the marketing send path checks it and blocks records without consent.
Notice & purpose limitation Purpose is stored per record; fields collected beyond the purpose are flagged in the design review.
Access & correction (data subject rights) One-person export answers an access request; edits are logged with actor and time.
Deletion / anonymisation Soft-delete then anonymise: identifying fields are overwritten and the audit row is retained (the log itself carries no personal data).
Security HTTPS, hashed passwords (Argon2/bcrypt), IC and TIN encrypted at the application layer with the key outside the database, role-based access, masked for non-admins, audit log on every sensitive view.
Breach notification (s.12B) Audit trail + encrypted backups make an incident provable, so the Commissioner and affected people can be notified within the required time.
Cross-border transfer Production must run in Malaysia. The white-list was removed by the Amendment Act, so a transfer assessment is needed if data leaves the country.

Scale check

The Data Protection Officer requirement applies above roughly 20,000 data subjects. At 106 contacts we are far below that — so no DPO appointment is required today. The system is nonetheless designed so the threshold can be met later without a rebuild (per-purpose consent, an audit trail and a breach-response path are the parts that are expensive to add after the fact).
